## Behavior and boundary

The computer still reads `observe(session, player)` and submits normal commands with `stepAI`. Bootstrap diagnosis now distinguishes people who can deliver, residence arrivals still due, existing builders, available tools, equipped smiths and reclaimable specialists. Zero settlers without future arrivals, builders without carriers, and a settlement without any legal hammer bootstrap are reported as unrecoverable; they do not receive speculative construction orders.

An idle pioneer can return to carrying, and an idle geologist can return its actual hammer. A surveying geologist is awaited rather than repeatedly dismissed during its work program. When an existing builder can continue construction, the surveyor keeps its hammer until a tool smith has its inputs. New construction crews wait while that sole hammer is being returned to the smith, so the smith can make replacement tools. Survey recruitment uses unreserved tool availability and cannot take a hammer already committed to a worker.

The player view exposes only its owner's remaining residence arrivals, busy-program flag and unreserved stack amount. Visible enemies receive none of these extra fields. Repeated observations preserve the simulation checksum. No balance, rules, save format, dependencies, resources or worker grants changed.

This is an explicit engineering AI policy under `roman-engineering` 0.8.0, digest `79d6f868c4b56d86fb54a65e739116bce25242d9d9e39225a1f871f53268de21`. It is not an original-game balance observation or native capability claim. The roadmap's pinned JSettlers revision `6ad8c4230a4aa4cd21840f8cb59a38344e41c3e0` remains implementation reference material; no original timings or AI policy were inferred from it in this change.

## Reproduction and observed results

`tests/unit/engine-ai-recovery.test.ts` retains all scenario buildings, piles, initial professions, tick bounds and commands. Its shared landscape is 96×96, seed 5, with the declared forest, granite, water/fish and coal mountain in `tests/fixtures/engine.ts`. Scenario sessions use seed 3 and ordinary AI decisions every 20 ticks. The generated critical-route fixture uses map/session seed 21 and the default 80-tick decision interval. Scenario equipment is declared at session creation and accounted for by the existing engine; the AI does not create it.

| Case | Actual public-session result asserted |
|---|---|
| Missing axe | An urgent order changes the smith's first real output to the axe. |
| Hungry coal mine | AI completes and staffs a fisher; fish is produced and consumed and coal extraction resumes. |
| Missing workers | A completed residence produces actual births, a woodcutter is staffed, and logs are produced. The declared 70% carrier setting is submitted through a normal command. |
| Full sawmill doorstep | Cancel the AI's first unfinished storage site through demolition, continue decisions, save/restore mid-recovery, then complete storage with actual stored planks and resumed production. Both sessions finish with identical checksums and no delivery shortage. |
| Missing hammer | Dismiss an idle geologist through the normal command; recovered hammer accounting increases, created goods do not, the sawmill completes and produces planks. |
| No carriers, idle pioneer | Return the pioneer, deliver and finish a residence, observe actual births and plank production. |
| Sole survey hammer and supplied smith | Preserve the surveyor before smith inputs arrive, then return its hammer; the staffed smith produces a replacement hammer. |
| Survey in progress | Await completion before dismissal, then recover construction and production without rejected AI commands. |
| Impossible population/tool bootstrap | After 1,200 ticks, diagnosis is unrecoverable, no construction is ordered and no production is fabricated. |
| Exhausted working area | Demolish the depleted stonecutter for its actual refund; preserve the woodcutter beside a forester. |
| Lost timber route/materials | Demolish the active sawmill, rebuild it and observe additional plank production; reclaim building refunds when possible and report impossible material bootstrap when refunds are insufficient. |
| Invalid input and repetition | Reject an invalid builder-dismiss command; subsequent AI commands succeed. Repeated decisions and a mid-recovery save replay conserve goods, equipment, reservations and people. |
| Owner visibility | Own arrivals/availability/busy status are visible, enemy fields are absent and observations do not mutate the checksum. |

Before the fixes, the new zero-population fixture failed with `population: recoverable true`; the no-hammer hungry-mine fixture failed with food, saw and hammer diagnoses all `recoverable true`; and the builder-only fixture failed with `population: recoverable true`. The original food and population tests accepted proposed construction without proving completion. The strengthened delivery replay exposed attempted survey recruitment using a reserved hammer. The surveying fixture exposed rejected dismissals while its work program was active. The supplied-smith regression initially recovered a hammer into a second builder instead of producing tools; the construction bootstrap wait fixes that observed loss of the legal recovery route.
